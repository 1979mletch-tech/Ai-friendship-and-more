# Accessibility acceptance criteria

- Every interactive control has an accessible name.
- Keyboard users can reach navigation, account controls, chat, conversation history, memory controls and destructive actions.
- Focus is visible and never trapped.
- Chat updates use a polite live region; errors use alert semantics.
- Form labels remain associated with inputs; validation is conveyed in text, not color alone.
- Destructive actions require clear wording/confirmation where data cannot be restored.
- Layout remains usable at narrow mobile widths and 200% browser zoom.
- Motion is non-essential and respects reduced-motion preferences when animation is added.
